# Archestra Codebase Architecture

Internal, code-grounded engineering documentation for anyone who needs to understand how Archestra is
built and why — contributors, new engineers, and reviewers. This is distinct from the user/admin-facing
product documentation in [`docs/pages/`](../pages/): those docs explain what a feature does for a user;
these explain how it's implemented, what the alternatives were, and what was traded away to get there.

Every claim in this set is grounded in the actual code as of the commit this was written against, with
repo-relative file paths so you can jump straight to the source. Where the code's own internal
`CLAUDE.md`/skill documentation had drifted from what the code now does, that's called out explicitly
rather than silently repeated — see [§10 of the tradeoffs doc](./15-design-decisions-and-tradeoffs.md#10-known-documentation-drift-found-while-building-this-document-set).

## How this was produced

This documentation set was generated by having multiple research agents independently read the actual
source (backend, frontend, Rust crates, infra config, tests) and write each file against what they
found, then reconciling cross-references and extracting the recurring cross-cutting themes into
[document 15](./15-design-decisions-and-tradeoffs.md). It reflects a point-in-time read of the codebase
— treat it the way you'd treat any architecture doc: a strong starting map, not a substitute for reading
the code it points to.
